# 0029 群聊按「有没有新进展」决定停不停，不再只认登记的项目
- 日期：2026-11-05
- 状态：有效（部分取代 [0017](0017-room-no-token-budget-autonomy.md) 的「保留发言次数类上限」）
- 决定：
  - 每轮发言次数 / 每人次数的上限，改成「没有进展时的上限」：一轮到了上限时，看这一轮里有没有新进展（群里新发了文件、任务看板有变化）。有进展就把计数清零接着推进，没有进展才暂停、提示「回复继续」。派活深度上限不变。
  - 没有进行中的项目也会自动接着推进：从用户上次发话以来，管理者派出去的活交回来了（至少一个成员回合做完），管理者这一回合结束、手上没有在做的事、也不在等用户时，系统再叫醒管理者安排下一步。两次叫醒之间没有任何新进展，就不再叫醒，提示用户一次。用户发话后重新计算。
  - 「进展」只看实打实的产出：群里新发的文件、任务看板状态变化。管理者反复派同样的活不算进展，避免无限叫醒。
- 原因：2026-11-05 用户「苏折竹ai短剧」群在写剧本、做生成，但软件里登记的项目 11 月 1 日已结束。所以每轮做完就停，要用户一遍遍说「继续」。同时每轮 8 次的上限，连「派一波 → 总结 → 再派一波 → 总结」都容不下（第 9 次被拦）。用户：「每次都自己停下来，还要我提醒继续」「就这样改」。
- 不做什么：不去掉防空转保护（没有进展照样停）；不在用户不知情时替用户做需要用户决定的事；不改项目的方案卡 / 确认流程。
- 影响：packages/server/src/rooms/（logic.ts、scheduler.ts、collab.ts）及对应单测、e2e group-collab 相关步骤。
