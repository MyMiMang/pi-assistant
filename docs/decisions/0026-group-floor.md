# 0026 群聊：群里只沟通，干活转后台
- 日期：2026-11-03
- 状态：有效（修订 0022 里「不整理还在进行中的项目」）
- 决定：
  - 成员的群回合做完 3 个工具步骤，或跑满 60 秒，或用户有话要交给管理者时，就让出发言位，在自己会话里继续跑完再汇报。
  - 没 @ 人的消息交给管理者，不塞给正在干活的成员。
  - 群里不单独显示只有过程、没有文字的消息。
  - 成员群会话超过 15 万 token 时，在它空闲的时候单独整理。
- 原因：2026-11-03 苏折竹群里，剪辑一个回合干了 40 分钟以上，整个群都在等它；剧本问题送给了剪辑；群里刷满了「1 个步骤 · 全部成功」；剪辑的群会话 47 万 token 从没整理过，每步约 5 分钟。用户确认按 super agent 思路改。
- 不做什么：不靠管理者判断要不要建任务；不把回合挪到新会话；不截断输出、不删原始记录；单聊不变。
- 影响：rooms/scheduler.ts、rooms/logic.ts、rooms/after-delivery.ts、agent-runtime、apps/web 群消息与 member-status.ts；设计见 design/group-floor.md。
