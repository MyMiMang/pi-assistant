# 0022 群项目交付后整理上下文，用户原话存进记忆
- 日期：2026-10-23
- 状态：有效（修订 0019 里「不为省钱提前整理上下文」这一条）
- 决定：三步走——① 唤醒消息不再重复系统规则里已有的规则和项目方案；② 群项目交付时，把用户本人在这个项目里说的原话和交付摘要作为正式记忆写给管理者；③ 群项目交付后（同群没有别的进行中 / 待确认项目、群空闲时），用 Pi 自带的整理上下文把管理者和参与成员的群会话整理一次，要求保留做成了什么、文件在哪、关键决定、答应了还没做的事。
- 原因：会话只增不减，迟早被 Pi 在任意时刻强制整理；在交付这个天然断点主动整理更安全，旧项目也不再干扰新项目、拖慢回复。目的不是省钱，有用的信息靠小结、记忆和文件保留。
- 不做什么：不新开会话（助理会忘了做过什么）；不截断工具输出；不整理还在进行中的项目；不删原始记录（留在会话文件里）；其他助理的话照旧只记草稿；单聊暂不自动整理；旧思考是否回传先实测再定。
- 影响：rooms/turn-prompt.ts、rooms/collab.ts（checkContext）、rooms/project-tools.ts、agent-runtime 的 compact、memory.retainTurn；设计见 docs/design/context-growth.md。
