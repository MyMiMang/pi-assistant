# 0018 目标清楚由管理者自己开启推进，干完交付结果
- 日期：2026-10-21
- 状态：有效（取代 0017 里「不在用户不知情时自动开自主推进 / 管理者发确认卡、用户确认才开」那部分）
- 决定：
  - 用户交代的事目标清楚、有明确交付物时，管理者自己开启自主推进（room_goal 直接开启，不再插确认卡），并在群里告知「我理解的目标是…，做到…算完成，现在开始推进，要改或要停随时说」——是通知不是提问，然后在同一轮里拆任务派出去。
  - 目标模糊（不知道交付什么、怎样算完成）时，管理者先问用户一两个关键问题，问清再开启；一问一答的小事、闲聊不开启。
  - 目标达成时，管理者先把最终交付物发到群里（做了什么、交付了哪些、还有什么没做），再结束自主推进。
  - 群聊顶部的按钮保留，用来看状态、手动开启、结束；旧的目标确认卡仍可显示和确认（兼容历史消息）。
  - 刹车不变：卡住三级阶梯、没进展只提醒一次、有后果的操作按权限档位审批、用户随时说「停」。
- 原因：用户定（2026-10-21）：「目标明确的情况下为什么不能自动推进，最终交付一个结果给用户？」手动开关 / 确认卡是多余的一步，也和「智能、按用户需要、交付结果」的定位矛盾。
- 不做什么：不让所有群默认一直处于自主推进（由管理者按目标是否清楚判断）；不在目标模糊时自己猜着开干。
- 影响：packages/server/src/rooms/（tools.ts 的 room_goal / room_goal_done、collab.ts 的 setAutonomy、index.ts / scheduler.ts / logic.ts 的管理者规则）、mock-provider、group-collab 单测与 e2e。
