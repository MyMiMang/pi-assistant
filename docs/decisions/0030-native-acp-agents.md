# 0030 新接的编程命令行工具按自己原本的方式干活，Pi 单独安装、完全分开
- 日期：2026-11-09
- 状态：有效
- 决定：orca 支持的、能走 ACP 的编程命令行工具都接进来，用「原生」模式：工具用自己的读写 / 命令能力在助理工作文件夹里干活，同时能用 Pi 的工具（助理电脑、浏览器、记忆、群聊、发文件），批准请求按这个助理的权限档位处理。Pi 不管用户装没装都另装一份自己用，配置 / 登录 / 规则 / 历史和用户自己的完全分开；App 里一键安装、点「登录」走工具官方登录、显示版本并由用户点击更新。
- 原因：「只借脑子」的接法每个工具都要单独改造、有的做不到、升级易坏，也用不上工具自身能力；原生模式只需一份很薄的配置，权限仍由 Pi 管。
- 不做什么：不用用户已装的那份、不改用户全局环境；不自动更新；不碰登录凭证；已接的 Claude Code / Codex / OpenCode / Antigravity 暂不迁移。
- 影响：设计见 docs/design/native-acp-agents.md；`cli-agents/acp-process.ts` 加原生模式，权限请求接 `requests.ts`；安装复用 `mcp-install.ts` / `cloudflared-bin.ts` / `downloads.ts`；`third-party.json` 固定版本。0023 里「Pi 的工具代替工具自带工具」只对已接的 4 个继续有效。
