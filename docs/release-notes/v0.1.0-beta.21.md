# 等待更省心，子代理模型更稳

- 需要等后台任务、子代理或 GitHub Actions 跑完，或者等到某个时间点时，助理改为**登记一次等待**，由程序定时检查结果，不再让模型反复询问、空转。等待期间不调用模型、不浪费 token；结果有变化才唤醒一次。等待状态可以直接查看、手动刷新或取消；任务被取消时会连带取消等待。唤醒通知如果没送到，会自动重试，服务重启后也会补投，不会静悄悄丢掉。
- 子代理的模型改为**每个助理自己的候选池**：在助理设置里勾选允许子代理使用的模型（可搜索、按服务分组、连续多选）。一个都不选就跟随主会话当前模型。派活时在候选池里按任务挑选；某个模型不可用（限流、服务不可用、模型不存在、鉴权失败、超时）时，只在候选池里换下一个继续，从已经做完的进度接着做，不重头再来、不重复已经完成的动作；每个模型最多试一次，试完就明确停下。工具执行失败、权限被拒、未知错误、你主动停止，都不会被当成模型故障去换模型，也绝不会偷偷用候选池以外的模型。每次换模型都会在会话里说明原因。旧版设置会自动迁移，不用手动改。
- 自定义模型服务的推理档位认得更准：能从 Pi 内置目录认出的模型会补回 xhigh / max 等更高档位，认不出的保持原样，不凭空添加。

本次仅提供 Apple 芯片 Mac（arm64）安装与更新包，Intel Mac、Windows、Linux 暂不构建。保留 beta.18 的完全权限行为：应用层全部免审批。

以上改动用本地 Mock 模型和真实服务进程验证：两端类型检查通过，任务等待、推理档位、子代理模型池等定向单测 62/62，真实 Mock 进程的子代理 fallback 冒烟通过，`e2e/model-ui.mjs` 六组与 `e2e/subagents.mjs` 全过，网页与服务端构建通过。全程不调用真实模型、不使用真实密钥。

已知限制：等待唤醒**不承诺只送达一次**，用等待编号做去重线索；跨服务重启时"已试过的模型"不持久化，重启后可能按新顺序各再试一次，但仍有上限、不会无限重试。自定义中转站是否真的透传 xhigh/max 未经过真实中转验证。缺少 Apple Developer ID 签名证书，更新后系统权限能否保留尚未解决；本版不宣称修复。真实模型与外部渠道账号仍需实际使用验证。
