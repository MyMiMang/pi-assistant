# Pi Assistant v0.1.0-beta.71

这一版主要解决「用反重力时一直在整理上下文、额度用得很快」，另外发送文件上限提到 2GB，中转站里的新 Gemini 也能看图了。

- **用反重力 / Claude Code / Codex 更省额度了**：
  - 以前几乎每发一条消息，都会和反重力重开对话、把整段历史再发一遍；长任务里 Pi 还会每一步都去整理一次上下文。现在和工具保持同一个对话，每轮只发新消息，上下文由工具自己压缩，Pi 不再替它整理。
  - 在中转模型和反重力之间来回切换时，切回反重力会接着原来的对话，只把它不在时的那段对话补给它，上下文是连贯的。
  - 上下文大小改用模型的真实值（例如 Gemini 4 Hydrogen 是 1M，以前写成了 200K）。
- **发送文件上限从 100MB 提到 2GB**：单聊和群聊都可以，上传时显示进度；用手机通过固定地址访问时也能发大文件。超过 30MB 的图片不直接给模型看，助理需要时用工具打开。
- **中转站里的新模型能看图了**：比如「灯灯国产」里的 gemini-4-hydrogen，以前因为模型太新、参数库还没收录，被当成不能看图，图片发过去前就被去掉了。现在会参考 Pi 自带的模型目录判断，更新后自动生效。
- 修了切换对话后输入框盖住最后一条消息（审批卡片的「批准」点不到）的问题。

这一版测试过的：
- 用测试数据跑过单元测试和浏览器测试：反重力 / Claude Code / Codex 的对话和来回切换、分块上传（单聊、群聊、取消、超限、清理）、看图判定。
- 在和你的 App 分开的测试环境里，用你的反重力账号（Claude 模型）和中转模型在同一个对话里来回切换 6 轮：每轮发给反重力的新内容只有几百 token、缓存一直命中、没有自动整理；切回来后答对了只告诉过中转模型的内容。
- 当时反重力里的 Gemini 报「User location is not supported」（网络出口地区不支持），没用 Gemini 实测；2GB 大文件没有用真实大文件、也没从手机实际试过。

提供 Mac Apple 芯片、Intel Mac、Windows x64、Linux x64/arm64 安装包。发布流程要求五个平台都构建成功，并且 Mac、Windows 的安装启动检查通过后，才开放自动更新。
