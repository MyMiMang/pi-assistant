# Pi Assistant v0.1.0-beta.45

这一版新增一家本机命令行模型：OpenCode。另外修了点「停止」后出现红色英文报错的问题。

- 可以用电脑上装好的 OpenCode 当助理的模型：
  - 在「设置 › 模型服务」里有一张 OpenCode 卡片，显示装没装、登没登录，装好后点「重新检测」就能用，不用重启。
  - 模型列表里会出现 OpenCode 能用的模型，名字后面写着来源，比如「DeepSeek V4.1 Flash（OpenCode Go）」。
  - 名字带「OpenCode Go」的用你的 Go 套餐；带「OpenCode Zen 按量」的从你的 OpenCode 余额里扣钱；带「免费」的不花钱，但免费额度有限。
  - 只把 OpenCode 当「大脑」用：它自带的读写文件、运行命令等工具都关掉，干活全部用助理自己的工具，照常走审批、记忆和助理电脑。等你审批很久也不会超时。
  - 不会读你的 OpenCode 全局设置和规则文件（也不会读 Claude 的 CLAUDE.md）。所以只认用 `opencode auth login` 登录的模型，写在全局设置里的自定义模型用不了。
  - 运行中插的话，会等它用完当前这个工具后再交给它。
  - 对话记录会出现在 OpenCode 自己的历史里。
  - 还没登录的话，在终端运行 `opencode auth login` 登录。
- 点「停止」后，以前有时会在底下出一条红色的「This operation was aborted」，看着像出错。现在统一显示灰色的「（已中断）」。所有模型都适用。
- 没有用量的那段回复，不再显示「0 → 0 token」。

这一版在隔离的开发测试环境里，用 OpenCode Go 套餐的 DeepSeek V4.1 Flash 实测过：建文件、读文件、列目录，接着上一轮聊天，运行中插话，中途停止，都正常。

没有实测的：
- 模型一次同时调多个工具的情况（只在模拟测试里验证过）。
- Windows 和 Linux 上的使用。
- 用量只显示最后一次模型调用的数（OpenCode 不提供整轮合计），费用不显示。

提供 Mac Apple 芯片、Intel Mac、Windows x64、Linux x64/arm64 安装包。发布流程要求五个平台都构建成功，并且 Mac、Windows 的安装启动检查通过后，才开放自动更新。
