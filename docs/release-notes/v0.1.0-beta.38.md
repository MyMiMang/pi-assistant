# Pi Assistant v0.1.0-beta.38

这一版修的是 beta.37 实际使用中发现的问题，主要在群聊「AI 团队」干活的过程里。

- 群聊里团队干活更顺了：
  - 群里不再出现只有一行名字、没有内容的空消息。
  - 管理者自己负责的活做完后会正常收尾，任务不再一直停在「待安排」；还有活没收尾时，不会提前交付项目。
  - 交付卡已经带着文件，不会再先把同样的文件单独发一遍；交付之后也不再补一句意思重复的话。
  - 一个阶段做完，管理者只说一次进度，不会把同样的话说两遍。
  - 管理者在等你看关键点、回答问题的时候，不会被反复叫醒，把「就等你回复」说好几遍。群顶部的状态也分开显示「等你回答」和「等待审批」，以前一律写成「等待审批」。
  - 项目进行中不再弹「存成技能？」的卡片打断推进，项目交付后才会问。
  - 管理者自己把一件活直接做完时，会停掉还在做同一件事的帮手，不重复干活，也不会再把同样的东西发进群里。
  - 方案里写分工时，名字后面带「（管理者）」或前面带 @ 也能认出来，管理者不用白白重出一次方案。
- 助理执行的某一步超过 1 分钟还没结束时，会在「正在运行」下面提示：可能在等系统的权限弹窗（比如问能不能访问「文稿」文件夹），看看屏幕上有没有；不想等了就说「停」。这行提示不会被输入框挡住。

提供 Mac Apple 芯片、Intel Mac、Windows x64、Linux x64/arm64 安装包。发布流程要求五个平台都构建成功，并且 Mac、Windows 的安装启动检查通过后，才开放自动更新。

本轮除了用隔离的临时数据和模拟模型做自动测试，还在单独的测试环境里，用真实模型和专门新建的测试助理、测试群完整跑了四个项目，验证了上面大部分修复。「管理者自己做完时停掉帮手」只做了自动测试，真实使用中还没碰到这种情况。
