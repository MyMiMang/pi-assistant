# Pi Assistant v0.1.0-beta.60

这一版新接了 15 个编程工具，现在 设置 › 模型服务 › 编程工具 里一共有 21 个。

- **新接的 15 个**：GitHub Copilot、Grok、Cursor、Amp、Devin、Goose、Auggie、Autohand、Cline、Droid、Kilo Code、Kimi Code、Kiro、Mistral Vibe、Qwen Code。
  - 它们和 Gemini CLI、CodeBuddy 一样，用自己原本的读写文件、跑命令能力，在助理的工作文件夹里干活。
  - 同时也能用 Pi 的工具（助理电脑、浏览器、记忆、群聊、发文件）。
  - 它们发来的批准请求按助理的权限档位处理。
- **怎么用**：在编程工具里找到想用的那个，先点「安装」，再点「登录」，然后在助理的模型列表里选它。
  - 登录方式看各工具：有的打开浏览器，有的打开一个终端窗口，有的需要在工具自己的设置里配置服务。卡片的「?」里写清楚了每个工具的情况。
- **和你电脑上的完全分开**：每个工具都由 Pi 单独装一份，从官方地址下载固定版本，并校验文件。设置、登录、历史都存在 Pi 自己的目录里。
- **不会自己更新**：
  - 各工具自带的自动更新，能关的都关掉了。
  - 另外加了一道保险：就算哪个工具自己去更新，也只会装进 Pi 自己的目录，碰不到你电脑上的 npm。
  - 你点「检查更新」才去查，点「更新」才会装。
- **个别平台暂不支持**：Amp 没有 Windows ARM 版，Kiro 没有 Windows 版，这些平台的卡片上会显示「暂不支持」。
- 工具装好但还没登录时，卡片上只显示「未登录」，不再冒出一行英文报错。

需要注意：
- Kiro 已按官方文档关掉自动更新，但我们固定的这个版本会不会严格照办，还没查实。
- 有些读文件的操作，工具不会逐个请求批准；Mac 上，工具存在系统钥匙串里的登录可能和你自己的共用。
- orca 列出的另外 12 个工具（如 Muse、Hermes Agent、Continue 等）没有对话协议，暂时接不了。

这一版测试过的：
- 用测试数据和假的安装包 / 假的工具程序跑过全部单元测试，以及 6 个编程工具的浏览器测试：没装 → 安装 → 登录 → 选为模型 → 对话 → 批准。
- 这 15 个新工具都还没有真实下载安装、用真实账号登录和真实模型对话过；也没有在 Windows、Linux 实机上试过。

提供 Mac Apple 芯片、Intel Mac、Windows x64、Linux x64/arm64 安装包。发布流程要求五个平台都构建成功，并且 Mac、Windows 的安装启动检查通过后，才开放自动更新。
