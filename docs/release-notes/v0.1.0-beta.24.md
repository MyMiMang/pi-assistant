# 修复外链点击、升级后重复向导、渠道删除按钮与单测污染

> 状态：**beta.24 候选（未打包 / 未发布）**。等主会话 review 与其余对话弹窗修复 commit 到齐后统一发布，仅 Apple 芯片 Mac（arm64）。待安装包真机点击 / 真实微信重连验证。

- 修复聊天里的外部链接（markdown 链接）左键点了没反应。原因是桌面主窗口加载的是本机页面，外链已被 Tauri 的 opener 插件拦截，但主窗口没有被授权调用「打开外链」命令，于是点击被吞。现在由页面显式接管：只放行 http/https/mailto，先请求系统打开，失败退回新窗口，再失败弹可见提示（含原地址与复制），不再静默。
- 修复升级后「明明已经配置过，仍然被强制重走首次设置向导」。原来向导状态依赖默认模型的实时解析，模型或凭据一时读不出就会被当成没配置。现在只看持久信号（向导标志、默认模型设置、助理数量），启动时自动补回丢失的向导标志；模型暂时不可用时给出「可恢复」提示，不再重走向导、不覆盖原配置。
- 修复设置 › 渠道里微信 ClawBot 连接的删除按钮点了没反应。原因是桌面窗口里原生 `confirm` 不弹窗且直接返回「取消」，所以删除根本没执行。现在改用应用内确认框，删除中禁用按钮防双击，失败会显示原因；凭据无法解密的连接也能删除（删除不需要解密）。
- 修复「侧边栏凭空多出一个助理」。根因是单元测试的数据目录没有强制隔离，在特定环境下把测试用的助理和一条微信渠道写进了用户真实数据目录（其渠道凭据解密失败，正是上一个版本「微信凭据无法解密」的来源之一）。现在测试数据目录强制指向临时目录并加了回归测试。

其他/边界：
- 助理电脑（虚拟机）上的外链真机点击、内置浏览器打开未验证；Rust 侧沿用白名单但本机无 Rust 工具链，未做 `cargo build`。
- 系统钥匙串弹窗的根因仍未查清，本次未改动钥匙串、也未清空用户数据。测试用的助理「小微」与那条测试渠道行仍保留在原数据目录，等你确认后再决定是否删除；你自己的微信连接未受影响。
- 首次向导「已配置被重设」只做了服务端与网页类型检查、7 项向导单测和 1 项 HTTP 级测试，未在安装包真机上跑升级路径。
