# 编程工具渠道的上下文：工具自己管，Pi 只补发增量

## 问题（2026-11-17 用户反馈：苏折竹用反重力一直在整理上下文、额度用得快）
用户 App 数据（只读）查到三个根因：
1. **几乎每条用户消息都重开工具对话、重发全文**：续用条件是「模型 + 工具 + 系统提示」的组合键不变（`toolsPromptComposite`），而 ext-memory 每轮把本轮召回的记忆塞进系统提示（`<memory>…</memory>`），组合键每轮都变 → `planTurn` 判成「换过模型」→ 新开对话、把整段历史渲染成文字（最多 6 万字）发过去，工具自己的上下文和缓存全丢。数据：对话中途的回复输入 23 万 token、缓存命中 0。
2. **Pi 替工具整理上下文**：Pi 按工具报回的用量判断阈值，工具进程里仍是全部上下文，Pi 一天整理 58 次，每次还要额外调一次模型。agy 1.5.4 自带自动压缩（更新说明里有 automatic compaction、/compact），本该它自己管。
3. **上下文大小写死 200K**：`agy models` 只给名字，接入时全部填 200K；Gemini 4 Hydrogen 实际 1M（Pi 目录：1,048,576）。

## 原则
- Pi 的会话记录是**唯一完整版本**；每个编程工具（反重力 / Claude Code / Codex / 原生 ACP 渠道共用 `channel-core`）里的对话只是副本。
- 用编程工具时，上下文由工具自己管；我们每轮只发它**没看过的**内容。

## 做法
1. **系统提示稳定**：渠道层把系统提示里的 `<memory>…</memory>` 块拿出来：组合键和启动参数只用去掉记忆块后的系统提示；本轮的记忆块放在这一轮发给工具的用户消息前面（标明「本轮相关记忆」）。其他每轮会变的段落如有，同样处理（实现时用两轮对比测出来，不靠猜）。
2. **增量补发**（取代现在「新增部分只能是用户消息、前缀指纹必须一致」的判定）：对照表记下工具**最后看到的那条消息**（稳定标识，如时间戳 + 内容哈希）。下一轮：
   - 那条消息还在 Pi 当前上下文里 → 续用工具对话，只发它之后的内容：用户消息照常；期间别的模型的回答、工具调用和结果渲染成文字，前面注明「你不在时的对话」。
   - 那条消息已被 Pi 整理进摘要 → 补发「期间的摘要」+ 摘要之后的消息。
   - 补发内容超过渠道上限（agy 6 万字）、换了模型 / 人设 / 工具、工具那边对话丢了 → 新开对话，发 Pi 整理后的历史（摘要 + 最近消息）；太长又没有摘要就先让 Pi 整理（沿用现在的 context overflow 交给 Pi 整理的路径）。
3. **Pi 不自动整理**：当前模型是编程工具渠道时，关掉 Pi 的按阈值自动整理（会话级 `settingsManager.setCompactionEnabled`，每次判断实时读取；切回普通模型再打开）。手动「整理上下文」照常；上一条「重开时太长先整理」的路径要保留可用。
4. **真实上下文大小**：编程工具渠道的模型按 Pi 内置目录 + models.dev 查（复用 `model-limits.ts` 的 `resolveLimits` / 同名匹配），查不到才用 200K。
5. **用量显示**：用编程工具时，界面的上下文占用以工具报回的用量为准（不拿 Pi 自己的历史估算）。

## 切换场景（必须覆盖）
中转 → 反重力（新开，发整理后的历史）→ 反重力聊几轮（每轮只发新消息）→ 中转（Pi 发历史，超窗先整理）→ 反重力（续用原对话，只补发中转那段 / 期间摘要）。反重力 ↔ Codex ↔ Claude Code 互切同理，各自记自己看到哪里。

## 不做
- 不改 Pi / agy 本体；不给普通 API 模型改记忆注入位置（中转站提示缓存也受影响，另行评估）。
- 不做后台自动对齐（只在下一轮发消息时补）。

## 验收
- 单测：记忆块拆分；增量补发的各分支（只有用户消息、含别的模型回答和工具、最后一条被整理进摘要、补发超限转新开、换模型 / 工具转新开）；编程工具模型不触发阈值整理、切回普通模型恢复；上下文大小查表。
- e2e（假 agy + Mock 中转模型）：中转 → 反重力 → 中转 → 反重力，断言第二次切回时续用原对话、发给 agy 的只有中转那段和新消息；连续多轮不重开。
- 开发实测（dev:live，测试助理）：真实反重力 + 一个中转模型来回切几轮，看缓存命中和每轮输入大小。由用户进行，本次未验证。

## 实现说明（2026-11-17，未提交）
- `context-input.ts` 统一拆出本轮记忆，稳定系统提示参与各家组合键；两轮对比测试确认记忆变化不会改启动提示和指纹。未发现需要按轮拆出的其他系统段落，规则/权限/人设变化继续触发重开。
- `sync-map.ts` 用最后消息的时间戳 + 内容哈希定位；锚点后的其他模型回答、工具参数/结果走共用转录，用户图片原样保留。锚点已整理时补摘要；补发超限、规则/工具/模型变化及续用丢失转 fresh。
- Pi 1.5.0 离线实测：关闭 compaction 后，overflow 也不会触发自动整理。因此 `context-ownership.ts` 在明确且无正文/工具调用的溢出后显式调用现有公开手动整理入口，仅恢复一次，用隐藏继续消息接着执行，不重复提交用户输入；中间 settled 延迟到恢复结束。
- 83b1ed24 的 `CliLive.summary` 防护保留并缩小职责：只保护挂起工具回填时显式整理造成的执行错配；不再以此触发阈值整理，也不阻止跨轮用摘要补发续用。
- 注册层共用 Pi 内置模型目录与 models.dev 的同名/日期快照匹配，未知保留各渠道预算；CLI 圆环只取当前工具最后有效用量，包含缓存，不加 Pi 历史估算。
- 自动化检查结果见 HANDOFF；假 agy + Mock 中转闭环记录在 `artifacts/cli-context-ownership-ui/`。
