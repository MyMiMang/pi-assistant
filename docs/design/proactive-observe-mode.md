# 主动做事先试运行 + 可以主动做的事（规则）

参考 [dsh-superagent](https://github.com/deepseek-ai/dsh-superagent-prototype)（MIT，研究原型）的 accept mode（off / observe / auto）和规则研判，按私人助理裁剪：不做多人白名单、规则版本化、恢复前重新校验权限。

## 现状
主动性引擎 `proactive.ts`：巡检、变化信号、到点跟进 → 助理判断 → `proactive_surface`（进提醒收件箱，受预算 / 免打扰 / 去重限制）或 `proactive_advance`（直接在相关对话里把事推进做完）。
`proactive_advance` 现在只靠主动等级和提示词 `ADVANCE_RULES` 约束：助理一判断就直接做，没有试运行阶段、没有用户写的规则，判断依据也不留记录。

## 要做的
1. **主动做事模式**（每个助理一份，放在现有主动设置里，名称 + 一行说明 + ?）：
   - 关：不能主动推进，只能发提醒。
   - 试运行：`proactive_advance` 不真推进，记成一张「本来会做」卡片进提醒收件箱：在哪个对话、打算做什么、依据哪条规则、依据的原话。卡片上两个按钮：「就这么做」（按卡片内容真的推进一次）、「这类以后别做」（记为否定，之后同类判断带上这条）。
   - 自动：照现在直接推进。
2. **可以主动做的事**（规则清单，每条一句大白话，例如「客户邮件问报价时，起草回复放进草稿箱，不发送」）。会变多，默认折叠、显示条数。
   - 助理调用 `proactive_advance` 时必须对每条启用的规则写「命中 / 没命中 + 理由」，并给出依据原话（照 dsh 的 `rule_assessments` + `intent_evidence`，结构化参数，不靠自由文本）。
   - 系统检查：自动模式下，「用户已经明确交代过的事」（现有 ADVANCE_RULES 第一条）照常放行；其余新发现的事至少命中一条规则才放行，否则只能发提醒。
3. **判断记录**：每次主动推进的判断（含试运行、被拦下的）记一行，提醒面板里只显示要你看的（试运行卡片）；健康状态不占地方。

## 不做
多人白名单、规则版本化与恢复前重新校验、跨渠道身份映射（这些是团队场景的问题）。

## 待你决定
1. 新建助理默认哪种模式：建议「试运行」。
2. 已有助理：建议保持「自动」（不改变你现在的使用习惯），设置里能改。

## 文件划分（初步）
- 纯逻辑新文件 `proactive-rules.ts`（模式判定、规则研判结果校验、卡片内容），`proactive.ts` 只许变短，接入处一两行。
- `ext-proactive` 的 `proactive_advance` 参数加规则研判字段；设置界面复用 `<Select>`、`<Fold>`、`<Help>`。
- 单测：三种模式下 advance 的去向、规则校验（缺研判 / 理由说没命中却标命中 / 未知规则 id 都拒）、「就这么做」与「这类以后别做」。
