# 让助理真的主动做事

用户的目标是助理能主动做事；现在基本不主动。参考 [dsh-superagent](https://github.com/deepseek-ai/dsh-superagent-prototype)（MIT，研究原型）的规则研判和 off / observe / auto 模式，但方向按用户决定：**默认自动、敢做**，试运行只是可选模式。

## 现在为什么不主动（2026-11-03 只读查用户 App，近 7 天）
- 巡检 74 次，**失败 21 次**，几乎都是「模型 5–16 分钟没动静」卡住（中转网络），还要从检查点重启再卡一次才放弃。
- **巡检看不到群**：`situation()` 只看非隐藏对话，群会话是隐藏的。「导演」的事全在群里，巡检 18 次只发了 1 条提醒、0 次推进，结论几乎都是「无」。群里其他成员没有单聊，`used` / `hasUnclosed` 判不出来，**一次巡检都没有**。
- **提示词太保守**：「宁缺毋滥，大多数时候应该什么都不发」。

## 要做的
1. **巡检看得见群**：situation 加「你在的群」：群里用户最近说的话、进行中的项目 / 任务（卡住的、等你的、快到期的）、群里约的事。群成员也算巡检对象（有群里的用户消息就算用过）。
2. **能在群里推进**：`proactive_advance` 可以指定群，在群里叫醒自己发言（复用 `rooms/followup.ts` 的群回合做法，回合原因写「主动推进」），群里先插一条可见小提示；群已停止就不推进、只记一条。
3. **敢做的规则**（替换 `ADVANCE_RULES` 和巡检规则里的保守说法）：区分「做事」和「打扰」——
   - 用户交代过、目标清楚、在原授权内的事：直接做完，再简短告诉结果；
   - 看得出能帮上的事（卡住的任务、快到期的事、反复手动做的事、明显的下一步）：主动去做或先做好草稿；
   - 对外承诺、花钱、破坏性改动、权限变更：仍然先问（审批不变）；
   - 推送条数上限只管「打扰你的提醒」，不限制做事。
4. **主动做事模式**（每个助理一份，放在现有主动设置里）：自动（默认，新建和已有助理都是）/ 试运行（只记成「本来会做」卡片，点「就这么做」才做、「这类以后别做」记住）/ 关。主动等级已经是「关」的助理不动。
5. **可以放心做的事**（用户写的规则，每条一句大白话，默认折叠显示条数）：对上规则的事，即使不是用户明确交代的，也可以直接做（扩大授权）。`proactive_advance` 结构化写明对上了哪条规则、依据的原话（照 dsh 的 `rule_assessments` + 证据），系统检查规则 id 真实存在。
6. **判断记录**：每次主动推进记一行（做了什么、依据、结果），提醒面板里可看；健康状态不占地方。
7. **巡检不再白卡**：后台巡检这种帮手，没动静的上限缩短（建议 3 分钟），卡住就结束这次、下次再来，不从检查点重启再卡一遍；断线照旧走自动重试。

## 不做
多人白名单、规则版本化与恢复前重新校验、跨渠道身份映射（团队场景的问题）。
