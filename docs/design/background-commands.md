# 长命令自动转后台（让插话、新消息不用等命令跑完）

参考 [dsh-superagent](https://github.com/deepseek-ai/dsh-superagent-prototype) 的做法：前台命令跑超过 5 秒就转成后台作业，助理下一步就能收到新消息；作业结束再把结果交给助理。

## 现状
- 助理的命令工具是 Pi 自带的 `bash`（参数只有命令 + 超时），命令一跑起来就要等它结束。
- 用户插话走 Pi `steer`，要等当前工具结束才送到；所以长命令期间插话会显示「等当前这一步做完送达」。
- 停止已经能立刻生效（会结束正在跑的命令），整件活也能交给后台帮手；缺的是**命令级**的转后台。

## 要做的
0. **范围**：只在用户看得见的单聊 / 群成员会话里转后台；帮手、后台任务、巡检没人插话，照旧等命令跑完（它们的会话一结束作业会被一起结束，转后台反而坏事）。
1. **自动转后台**：命令跑满 5 秒还没结束，工具先返回「已转到后台（编号 job_x）+ 目前为止的输出；结束后会告诉你」，进程继续跑。助理这一步结束，插话马上能被看到。
2. **结束后交回结果**：作业结束时，结果（退出码 + 输出末尾）：
   - 助理还在这一轮里 → 作为一条系统插话送达（复用 `interject.ts` / steer）。
   - 助理这一轮已结束 → 按现有唤醒机制开一轮让它接着处理（同一对话，用户可见一条小提示「后台命令结束」）。
3. **两个配套工具**：查看 / 等待某个作业的输出、结束某个作业。
4. **上限**：每个作业最多 30 分钟，超时结束并告诉助理。用户点「停止」→ 这一轮停下，这一轮起的后台作业一起结束（和现在停止的含义一致）。
5. **审批不变**：命令启动前照旧走 ext-approval（按 `bash` 拦截），转后台不影响审批和权限档位。
6. **提示词**：后台作业没结束前不能说「做完了」；一轮结束时还有作业在跑，状态显示「后台命令在跑」。

## 怎么接（不改 Pi）
- Pi 公开导出了 `createBashToolDefinition` 和可替换的 `BashOperations`；会话创建时用 `excludeTools` 去掉自带 `bash`，换成我们包了一层的同名工具（工具名、参数不变，模型和审批规则无感）。
- 助理电脑（`sandbox.ts` 的 docker exec）和本机两条执行路径都要覆盖；Windows 的 powershell 同样处理。
- 先做实测：工具返回后子进程不会被 Pi 杀掉；输出缓冲上限；服务重启时后台作业怎么记（标「中断」，下一轮告诉助理）。

## 不做
后台作业跨服务重启继续跑（重启就结束，告诉助理重新确认）。

## 测试
- 单测：5 秒内结束的命令行为不变；超过 5 秒转后台并返回编号；结束后结果送达（这一轮内 / 这一轮已结束两种）；30 分钟上限；停止时一起结束。
- e2e（Mock 模型）：长命令期间插话立即被处理（不再显示「等当前这一步做完送达」）。
