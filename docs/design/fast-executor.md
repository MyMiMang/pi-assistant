# 电脑操控：快速执行者（大模型定步骤，决策模型逐步挑）

## 为什么
- 2026-11-03 实测：一次网页表单任务一共 14 步、121 秒。cua 每个动作只要 0.1–1 秒，**每一步约 8 秒花在大模型想下一步上**。
- 很多时候大模型早就知道接下来要做什么了，比如「名称框填 X → 下拉选 2K → 上传这 3 张图 → 点提交」，可它还是一步一调模型。
- Jev（TypeSafe 的决策模型）专门做「从给定选项里挑一个」，官方称一次 70–500 毫秒，还会给出概率。cua 官方示例 `libs/cua-driver/examples/jev-use` 就是这种分工：
  - 程序列出完整的候选动作；
  - Jev 只返回其中一个编号，不能自己编造坐标、编号或要填的值；
  - cua 执行这个动作；
  - 成功与否另外核对，不信模型自己说的。

## 做法
1. **新工具 `computer_quick_steps`**（只在「操作电脑」开着、并且配了快速执行模型时才提供）。
   - 参数：
     - 目标：网页 `tab_id`，或者窗口的 `pid` + `window_id`；
     - `steps`：每一步写 `{ do: click | type | select | check | press, what: "名称输入框", value?: "苏折竹" }`；
     - `stop_if`（可选）：遇到什么情况停下。
   - 大模型写一次，执行者自己跑完。
2. **每一步怎么跑**（服务端 / 扩展里的纯循环，不调用大模型）：
   1. **读一次结构**：网页用 `get_browser_state`，窗口用 `get_window_state`，都不截图。
   2. **列候选**：按动作种类过滤元素（填写只看输入框，点击看按钮和链接，选择看下拉）。按和 `what` 的文字相近程度取前 24 个，每个写成「编号 + 角色 + 名字 + 当前值」，另外加上「重新读一次」和「拿不准」两个选项。
   3. **问 Jev**：用 Pi 公开的 `classify`（choice 问题），问「第 i 步：{do}{what}{value}，选哪个」。状态里带上目标、已做过的步骤、表单的当前值。
      - **看图**（Pi 1.5.0 起可用）：分类模型的 `input` 含 `image` 时（如内置 `jev-latest`），把这一步的窗口截图作为 `ClassifierContext.images` 一起传，帮 Jev 分清长得像的元素（两个都叫「确定」的按钮、只有图标的按钮）。Pi 会自动带上 TypeSafe 的图片开关请求头。模型不支持看图就只传文字，照样能用。
      - 只截一张、压到长边 1280 以内；结构里已经能唯一确定的一步（候选只剩 1 个且文字完全对上）不截图，省时间。
   4. **判断**：概率 ≥ 0.6，而且不是「拿不准」，才执行。
      - 选了「重新读一次」：最多再读 1 次。
      - 其他情况：停下，交回大模型。
   5. **执行**：拼成具体的 cua 调用。比如 `browser_type(ref, value)`、`browser_select`、`browser_click`；窗口用元素编号的 `click` / `type_text`。**要填的值只来自大模型写的 `value`，Jev 只挑元素。**
   6. **核对**：再读一次结构。填写和选择要看到值真的变了；点击要看到页面有变化，没变化就停下，交回大模型。
3. **安全**：每一步执行前，用和 `tool_call` 闸门**同一个检查函数**判断档位和敏感动作（付款、发送、删除、提交表单、受保护快捷键）。
   - 只看档位：拒绝。
   - 要批准的动作：执行者不自己批。实现时改成更简单的做法：每个动作都经 Pi 公开的 `ctx.executeTool()` 调用，**和大模型直接调用走同一个 `tool_call` 闸门**，所以照常弹审批卡；用户拒绝就在这一步停下交回大模型。工具本身声明 `openWorldHint:false`，通用审批不会为它再多弹一张卡。
   - 完全权限：按档位放行。
4. **返回给大模型**：每一步做了什么、选了哪个元素、概率多少、核对结果、用了多少毫秒；停下时说明原因，并附上当前页面的简要结构，方便大模型接着做。
5. **设置**：「操作电脑」里加一项「快速执行」，用一行字说明做什么；「?」里写清楚分工和风险。
   - 下拉框选一个已配置的决策模型（Pi 的 classifier 目录）。默认选第一个可用的 Jev，没有就不提供这个工具。
   - 可以关闭。
6. **提示词**：在电脑操控说明里加一句：已经确定的连续几步（填表、选择、逐个点）用 `computer_quick_steps` 一次交出去；拿不准的一步、需要看画面判断的一步，还是用普通工具。

## 不做什么（这一版）
- 不用 Box：Pi 1.5.0 的分类接口还没有 Box（框出画面位置）。所以 Jev 只在程序列出的候选里挑，不靠它给坐标。等 Pi 加上后手动升级再考虑，不改上游。
- 看图在 TypeSafe 官方仍标为预览：单测和设置里都允许只用文字，看图失败（返回错误）时这一步自动退回只传文字再问一次。
- 不让 Jev 规划步骤，也不让它生成要填的值。
- 不在执行者里自动批准任何需要审批的动作。
- 不接 CUA-S1：它要本地跑约 9 GB 的模型，官方说还是研究版。

## 验证
- 单测（Mock 分类器 + 假的 cua 结构）：
  - 候选过滤和排序；
  - 概率阈值；
  - 「拿不准」和「重新读一次」；
  - 敏感动作停下；
  - 值只来自大模型；
  - 核对失败时停下；
  - 模型支持看图时带图、不支持时不带，看图出错退回文字。
- e2e：`PIA_HOST_CONTROL_DRY_RUN` 加 Mock 分类器，跑一遍工具的往返。
- 真机：在 `dev:live` 用测试助理 + 本地测试表单（和 2026-11-03 测的是同一个任务），用户自己登录 Jev 渠道。对比修改前的 121 秒 / 14 步，记下实际耗时和交回大模型的次数。

## 实现后的状态（2026-11-04 / 05）
- 由 Pi 开发助理（DeepSeek）按实现方案写，Claude 审查后修了 3 处（工具声明不直接碰外部、按键不核对页面变化、界面「会看截图」按模型能力判断）。
- 单测通过；全量 `npm run check` 通过；设置界面在临时 Mock 环境截图（1280 / 390，无溢出）。
- 真机实测（dev:live，测速助理 + gpt-6.1-sol + TypeSafe jev-latest，用户同意、独立 Chrome，本地表单：填名称 / 选两个下拉 / 勾选 / 传 3 张图 / 提交）：
  - 第一次 305 秒：大模型用了快速执行，但第 1 步就停下。根因是 ext-computer 的 `tool_result` 钩子追加文字时没带回 `structuredContent`，Pi 会删掉它，嵌套调用拿不到 `refs`。已修（钩子原样带回 + 单测断言）。cua 网页结果的可操作元素确实在 `refs`（`{ref, role, name, value, actions}`），解析不用改。
  - 修后 108 秒（基线 121 秒）：6 个动作一次调用 4.4 秒全部做完并核对通过；剩下的时间是开浏览器 / 绑定 / 打开网址 / 读页面这些准备步骤里大模型每步约 10 秒的思考。
  - 这次 6 步名字都完全对上，**没有走到问 Jev 的路径**；Jev 本身单独验证过（4 次都选对，连上后每次 0.6–1.2 秒）。名字不规整时的真机表现**未验证**。
- 没做：`stop_if` 只是参数，没有行为；网页里按键、窗口里上传交回普通工具。

## 第二版真机测速（2026-11-05，dev:live，测速助理 gpt-6.1-sol + Jev，本地测试表单）
- 任务和上次一样（含表单里不存在的「素材类型」）：127 秒、9 轮大模型。`hostpc_quick_open` 10 秒打开并绑定，填表 + 上传 6.4 秒、提交 2.7 秒，Jev 全对；多出来的轮次：大模型抄 target_id 抄错一位（读页面失败重读）、为了找不存在的字段带截图重读、填表和提交分两次交。
- 任务和表单对得上（名称 / 分辨率 / 比例 / 高清 / 3 张图 / 提交）：92.8 秒、7 轮，整张表一次 `hostpc_quick_steps` 3.9 秒做完；这次它复用了已开着的 Chrome，没走快速打开。
- 结论：执行已经不是瓶颈，时间几乎全在大模型每轮 8–15 秒的思考。目标模式这两次都没被用上。下一步（第三版，待做）：`target` 可省略、默认用这个会话最近打开的目标（不用抄长 id）；`quick_open` 可带 steps / goal 一次做完「打开 + 填 + 提交」；目标是 4 轮左右。
