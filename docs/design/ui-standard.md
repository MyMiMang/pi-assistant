# 界面标准

用户的感受：程序整体太复杂，但功能必须专业。目标是**让用户一眼判断每一项是做什么的**，而不是把说明删光、只剩开关。

## 每一项怎么写
- **名称 + 一行大白话**：说清楚这一项对用户有什么用（不是技术原理）。例：「高级记忆 · 理解意思再去找，比关键词更聪明」。
- **更深的解释放「?」**：用 `ui.tsx` 的 `<Help>`。原理、限制、注意事项都放这里。
- **不用开发用语**：界面上不出现 provider、payload、token budget 这类词，必要时放进「?」。

## 专业参数
- 放进默认折叠的「高级」区（`<Fold>`），每个参数都有默认值，不填也能用。
- 例：中转站的请求头、按协议单独填地址、上下文长度 / 最大输出都在「高级」里。

## 会变多的列表
- 默认折叠，标题显示数量（如「其他 12 个未启用」），展开后限高、内部滚动。
- 已启用 / 正在用的直接列出，其余收起。
- 例：助理电脑页的助理列表、能力页的技能和扩展、中转站的模型列表（可搜索筛选）。

## 一页一个焦点
- 每页只有一个主要任务；次要入口收进折叠区或「更多」。
- 状态（正常 / 慢 / 出错）用小标记 + 一句话，细节放「?」。出错不能静默：要让用户看得到。

## 必须复用的组件
- 模型 / 思考 / Fast：`ModelPicker`（输入框那一套），不另做设置版控件。
- 折叠 `Fold`、说明 `Help`、下拉 `Select`、确认 `useConfirm`、标签栏 `ResponsiveTabs`、串行保存 `latest-write.ts`。

## 助理详情（经典布局，已批准）
- 64px 居中头像；单行文字标签，放不下的进「更多」；八个分类：概览 / 模型 / 资料 / 能力 / 任务 / 记忆 / 文件 / 电脑。
- 模型、思考强度、Fast 各自即时保存；资料显式保存，草稿切换标签时保留。
- 视觉见 [agent-details-classic.md](agent-details-classic.md)，功能契约见 [agent-details-functional.md](agent-details-functional.md)。
