## 先分开验证两件事

- **远端地址和日常操作**：手机使用远端 HTTPS 地址及普通设备 Bearer 授权。地址簿只负责查找地址，不是固定地址访问的前提。用回环内测试 HTTPS 边缘和临时 Pi 服务，模拟 HTTPS 终止、HTTP 回源；验证 B 本机批准的普通设备经这条线路访问聊天和撤销。普通设备仅用于测试线路能力，不是桌面配对方案。
- **桌面独立领取**：现有直连规则不变。命名隧道用独立 `/api/desktop-edge-pair` 契约及状态；回源 HTTP 不产生可信直连上下文。目标机本机把绑定在线固定地址和身份的五分钟邀请交给发起端；发起端沿精确 HTTPS 地址校验证书、禁重定向，并用邀请公钥核验与地址、身份和新随机数绑定的服务签名，才提交桌面认领。批准、申领证明、领取和激活保持独立，授权可单独撤销。来源头、Host 或声明的协议不是领取凭据。

## 最小兼容候选与缺项

复用固定 HTTPS 地址、既有撤销和有限业务 API；桌面壳以独立设备身份提供按目标隔离的具名操作，网页不持有设备凭据。已接受与手机相同的边缘 TLS 信任（边缘可见请求）；服务签名证明对端持有邀请中确认的公钥对应的私钥，不把它描述成端到端流量加密。未接通桌面壳、系统保护存储以及发起端邀请输入界面。不改隧道、手机接口，不引入 TURN。

## 实验与后续原生验收

目前可跑两类隔离测试：正式 React 界面显式注入测试端口，覆盖切回本机、草稿隔离、迟到、断线与重连不重发；真实 Node 双实例 + 临时 TLS 验证直连和桌面领取。手机线路夹具另验证 HTTPS 边缘与回源后的普通设备行为，三者均不代表真实异地。

原生验收需要可复现的 Mac/Windows 构建环境、隔离系统用户与系统保护凭据存储、非在用的目标 Mac、经批准可访问的测试固定入口或等价线路，以及至少两套真实独立网络及联系人确认。由目标 Mac 生成普通用户可用的桌面邀请，不要求手配测试证书。分别实录原生 Mac→Mac 和 Windows→Mac 的读聊发任务、切回、断线/重连、撤销及重启后的凭据保护。未获授权前不试探在用域名、不往第三方发送连接数据。
