2026-10-18，用户已同意推进任务与单次执行分层，询问任务看板是否接入。状态：**候选已实现并通过定向验收，未发布 / 未 commit / 未 push / 未打包**；独立工作树 `task-responsibility-integration`，基于本地main `5850c11`，不改beta.32已验收候选。实际实现、测试确数、最后失败与未验见 [检查点](../../progress-snapshots/work-items-checkpoint.md)。

## 用户流程

聊天是主要入口。管理者判断长期责任是否需要单独记录，形成任务并分配；临时问答与每个工具步骤不自动生成任务。任务看板是同一份数据的可视入口，用户可查看负责人、进展/阻塞、交付与验收，并可继续、暂停、改派或取消；不要求用户维护两份记录。

群聊顶部加入明确的「任务」入口。桌面按状态分组，手机用可切换状态的纵向列表，避免宽列横向拖动。任务摘要展示名称、负责人、当前状态和最近进展；打开详情看需求/完成标准、结果、执行历史及当前可用动作。第一期不用拖拽、复杂依赖图、甘特图或多级项目空间。

## 领域边界

- **任务责任**：独立id、可信来源容器和来源消息、需求、负责人、交付/完成标准、状态、最近进展/阻塞与核验结果，跨多次执行保留。
- **单次执行**：现有 `room_turns` / `tasks` / `subagents` 继续各自调度，只关联任务id与执行尝试；不重复造一套runner。数据设计兼容普通助理对话，首期主要在群内贯通。
- **验收**：执行结束最多变为待核验，失败/中断保留失败原因或阻塞；不能把模型正常停下、成员发了回复、命令exit0直接等同目标完成。成员提交结果，管理者或用户核验后确认；核验依据来自实际可读产物/检查，不能由服务端猜语义成功。
- **等待**：使用现有事件/持久等待机制，不轮询模型，不因为无人回答而持续占推理。
- **资源**：首期保留群内串行调度和现有并发限制，不盲目并行操作共享桌面/文件。并行调度扩展另需资源隔离证据。

首期状态为待安排、进行中、受阻、待核验、已完成、已暂停、已取消。持久业务状态与当前有没有执行分别呈现，取消/暂停的终态动作不能只改卡片外观。任务保留完成标准、核验记录与修订号；执行关联带当时的任务修订/负责人，晚回结果只追加历史。任务详情关联现有room_turns/tasks/subagents，不再建立自己的模型调度器。

## 必须成立的约束

1. 创建/改派任务责任与启动执行逻辑分开；一个用户动作可组合完成两者。仅写责任记录不偷偷调用模型。
2. 任务、来源消息、负责人和执行关联必须校验同一容器，管理者可派活/验收，普通成员只能提交自己的结果/阻塞，不能伪造别人的身份。已有普通@消息规则保持。
3. 编辑/改派/取消后，旧执行结果可留作历史，不能覆盖当前任务责任或把新一轮误标完成。使用修订号或精确执行代次作比较，不靠模型提示词保证。
4. 重启恢复复用现有执行记录；未知副作用先核验，不能重建任务、重复dispatch或自动报完成。任务记录与看板状态持久化。
5. 暂停停止后续自动安排；已发出的动作可能已发生，展示真实已知状态。移出成员需标明待改派，不能自动把未完成责任交给管理者又暗中启动；删除容器按现有删除语义清理本容器任务与关联，不留隐形继续执行。
6. 看板修改失败可见、保留草稿；断WS/重连/迟到响应不能污染另一群；有界列表/详情，避免全量历史或不断轮询。
7. 官方Pi公开SDK/自有模块，复用已有UI/权限/主题/文档与事件总线；无Rovai代码或依赖。

## 验收

至少覆盖“管理者创建长期任务并派活→成员提交→待核验→退回修改→原任务新执行→管理者核验完成”，以及失败/等待/取消/改派/旧结果/重启。验证任务与执行独立，真实mock Pi流程贯通，持久化与权限边界正确；桌面与390px窄屏验证正文可见、错误与动作边界。所有测试用临时根、内存凭据及Mock，早于任何config/db导入；不读取生产DB或使用真实收费模型。

## 实现状态（2026-10-18 检查点）

- 独立模块 `packages/server/src/work-items.ts`：`work_items` / `work_item_runs` / `work_item_events`；状态机、修订、执行代次、actor 绑定、晚结果、自动重试上限（3）。
- 执行仍走 `rooms` 的 `room_turns`（新增 `work_item_id` / `work_run_id`），不新建 runner；`work_create` 直接派发与 `room_assign.workItemId` 排队认领两条路径。
- 工具：`work_create` / `work_submit` / `work_verify` / `work_list` / `work_update`；HTTP 看板与「在群里说」反馈入口。
- 自然语言纠正：编号 / 任务名 / 引用结果卡定位；多任务只追问不猜；目标/范围/完成标准不清时只记待安排，不擅自执行；退回带明确改进要求且授权仍有效时自动安排原任务下一次执行，暂停/取消/群上限/失败不自动复活。
- UI：群顶部「任务」入口、桌面分组、390 纵向列表/筛选、详情、执行历史、失败保留草稿；只按打开/动作/bus 刷新，不轮询。
- 实测：长期任务单测 13/13、群聊原路由 23/23、两端 typecheck 0、web build 通过、真实 PiMock+Chrome e2e run13 通过（成员真写文件、管理者 read 后核验、二次执行、失败可见、390、持久化）。截图 `docs/screenshots/work-items/`。
- 未验：真实云模型对自然语言纠正的稳定性；失败后管理者 followup 的真实 Mock e2e（代码已把 assign 失败计入批完成，只有单测/代码路径）；真机与其他主题。未发布。
