# 技能建议：具体用途与等待收口

2026-10-18 · beta.32 候选。原子代理实现经主会话复核后调整，以下为最终行为，覆盖早期“同一轮阻塞等待用户”的方案。

自动建议只把多步/重复任务记成候选。当前会话空闲时，用一次正常模型推理拟定具体名称、做什么、使用时机、结果；说不清用途就结束。无独立 LLM 服务或模型切换，但会产生当前模型的正常用量；设置 Help 已说明。

`skill_propose` 只在普通聊天提供。宿主检查候选 id、助理/对话归属、一次性状态、3分钟提交窗口、字段长度、非空、非泛泛模板与非纯工具名。`purpose` 列审计实际展示文本；旧记录为空，迁移幂等。不从工具调用参数猜已产出文件，不将 stopReason 或普通回复等同任务完成。失败/中断/泛泛“继续”等不给新建议。

出卡后工具立即返回 pending，模型结束本轮，用户晚点回答仍有效。点击同意才记 accepted，再由原会话继续查重/保存；未同意不保存，更新照常 diff 审批。重启清候选/旧卡，停止或取消作 expired，不永久屏蔽该话题；未出卡的 expired 不消耗节流。原同对话24h、同助理2h、拒绝话题/关闭策略保留。

定向服务端33项、连Fast协议回归共47项通过；群服务器另外21项，总68。`e2e/skill-proposal-purpose-ui.mjs` 经真实Pi Mock→候选→用途卡→空闲等待→同意→查重→落库全链通过；桌面1280/手机390截图已主会话实际查看，文字与卡边界正常。测试不接真实服务商、无付费模型。

限制：用途质量依赖当前模型，宿主只能拦明显泛泛/无效字段，不能机器证明语义准确或与最后技能正文完全一致。内部触发消息隐藏，普通 assistant 输出仍按原运行时显示；提示要求提议轮不输出正文，真实模型遵循程度未付费测量。新方案在用户同意后有一轮正常续跑，与阻塞工具方案相比多一次起轮，以换取用户稍后处理时助理继续可用。未做全量测试/原生App/跨平台任务验收。

整体检查、命令与发布状态以 [beta.32收口](beta32-final-validation.md) 为准。
